## 1. 概述

修改 SSH 端口最怕的是「改完连不上、把自己锁在门外」。本工具围绕这一风险设计，核心思路：

- **先备份再动手**：每次修改前自动备份 `sshd_config`；
- **过渡期双端口并存**：新端口验证通过前，旧端口保持可用；
- **语法不通过就回滚**：`sshd -t` 校验失败自动还原；
- **验证后收尾**：确认新端口能登录后，再用收尾脚本关闭旧端口。

> 本工具仅修改本机 SSH 配置与防火墙。云服务器还需在**云厂商安全组**中放行新端口（见 [第 9 节](#9-防火墙与云安全组)）。

## 4. 快速开始

### 方式一：一条命令安装 + `sshh` 进面板（推荐）

```bash
# 1. 安装（内网/国内建议用 jsDelivr 线路）
curl -fsSL "https://cdn.jsdelivr.net/gh/Swordee/NEW1@v2.8/Debian%20SSH/install.sh" | sudo bash

# 2. 让别名生效（或直接新开一个终端）
source ~/.bashrc

# 3. 输入 sshh，进入面板
sshh
```

面板里按数字选择即可，常用流程是 `2) 更改 SSH 端口` → 另开终端验证 → `3) 移除旧端口`。

### 方式二：手动跑脚本

#### 第一步：更换端口（保留旧端口过渡）

```bash
sudo bash change_ssh_port.sh
```

按提示输入新端口 → 确认 → 选择「临时保留旧端口 (Y)」。

#### 第二步：验证新端口

**另开一个终端窗口**（不要关掉当前会话）：

```bash
ssh -p 新端口 用户@服务器IP
```

能成功登录即说明新端口生效。

#### 第三步：关闭旧端口

```bash
sudo bash remove_old_ssh_port.sh
```

输入要移除的旧端口 → 确认，旧端口即彻底关闭。

## 5. 主脚本：change_ssh_port.sh

### 5.1 参数说明

| 参数 | 简写 | 说明 |
| --- | --- | --- |
| `--port <端口>` | `-p` | 指定新端口，省略则交互输入 |
| `--yes` | `-y` | 跳过所有确认（自动化模式） |
| `--keep-old` | — | 过渡期保留旧端口 |
| `--no-keep-old` | — | 不保留旧端口，直接只监听新端口 |
| `--firewall` | — | 自动放行防火墙端口 |
| `--no-firewall` | — | 不改动防火墙 |
| `--dry-run` | `-n` | 预演，仅显示将执行的操作，不改任何文件 |
| `--help` | `-h` | 显示帮助 |

### 5.2 使用示例

```bash
# 1) 纯交互（推荐新手）
sudo bash change_ssh_port.sh

# 2) 指定端口，其余交互
sudo bash change_ssh_port.sh -p 2222

# 3) 全自动：改端口 + 保留旧端口 + 放行防火墙
sudo bash change_ssh_port.sh -p 2222 -y --firewall

# 4) 全自动：只监听新端口，不放行防火墙（自行处理）
sudo bash change_ssh_port.sh -p 2222 -y --no-keep-old --no-firewall

# 5) 预演：先看会改什么，不做任何修改
sudo bash change_ssh_port.sh -p 2222 -n
```

### 5.3 执行流程

1. **环境检查**：root 权限、`sshd_config` 是否存在；
2. **读取当前端口**：`sshd -T` 获取实际生效端口（含 Include）；
3. **输入/校验新端口**：数字、1–65535、非当前端口、未被占用；
4. **确认**：展示变更内容，二次确认；
5. **备份**：`/etc/ssh/sshd_config_backups/sshd_config.<时间戳>.bak`；
6. **Include 检查**：发现 `sshd_config.d/*.conf` 里有 `Port` 时提示并可选注释；
7. **写入配置**：清理旧 `Port` 指令，在文件顶部写入新 `Port`（可选保留旧端口）；
8. **语法校验**：`sshd -t`，失败自动回滚；
9. **防火墙**：按策略放行新端口；
10. **重启服务**：`systemctl restart ssh`；
11. **监听验证**：确认新端口真正在 `LISTEN`；
12. **安全提示**：输出测试与回滚命令。

## 6. 收尾脚本：remove_old_ssh_port.sh

### 6.1 参数说明

| 参数 | 简写 | 说明 |
| --- | --- | --- |
| `--port <端口>` | `-p` | 指定要移除的端口，省略则交互 |
| `--yes` | `-y` | 跳过确认 |
| `--dry-run` | `-n` | 预演 |
| `--help` | `-h` | 显示帮助 |

### 6.2 使用示例

```bash
# 交互
sudo bash remove_old_ssh_port.sh

# 指定移除 22 端口
sudo bash remove_old_ssh_port.sh -p 22

# 全自动
sudo bash remove_old_ssh_port.sh -p 22 -y
```

### 6.3 行为说明

- 自动列出当前所有生效端口；
- 只允许移除「存在且非最后一个」的端口（防止把自己锁死）；
- 备份 → 精确删除该 `Port` 行 → `sshd -t` 校验 → 重启 → 验证剩余端口监听；
- 任何一步失败自动回滚。

## 7. 工作原理

### 7.1 配置修改逻辑

脚本不会「盲改一行」，而是：

1. 删除主配置中所有 `Port` / `#Port` 指令（避免重复冲突）；
2. 在文件**顶部**重新写入规范的 `Port` 指令（可选同时写旧端口）；
3. 保留其余配置原样。

修改后大致如下：

```sshconfig
# === change_ssh_port.sh v2.4 @ 2026-10-31 23:00:00 ===
Port 22        # 过渡期保留（选了 --keep-old 才有）
Port 2222      # 新端口

# ...原有配置保持不变...
```

### 7.2 Include 处理

Debian 12 等系统的 `sshd_config` 顶部常有：

```sshconfig
Include /etc/ssh/sshd_config.d/*.conf
```

若被包含的文件里也有 `Port 22`，即使主配置删掉，旧端口仍会生效。脚本会：

- 扫描所有被 `Include` 的文件；
- 发现 `Port` 指令时明确提示文件路径与内容；
- 征得同意后注释掉这些 `Port` 行（并备份）。

### 7.3 为什么写在文件顶部

`Port` 属于可多值指令，且 `Match` 块之后的指令会归入该块。若把 `Port` 追加到文件末尾，一旦配置以 `Match` 块结尾，新 `Port` 会被错误地归入匹配块。写在顶部可规避此问题。

## 8. 安全机制

| 机制 | 说明 |
| --- | --- |
| **自动备份** | 改动前备份到 `/etc/ssh/sshd_config_backups/`，文件名带时间戳 |
| **语法校验** | `sshd -t` 不通过则立即回滚，本次零改动 |
| **trap 兜底** | 脚本异常退出时自动还原备份并重启服务 |
| **双端口过渡** | 默认保留旧端口，验证通过后再关闭 |
| **防锁死** | 收尾脚本禁止移除最后一个端口 |
| **监听验证** | 重启后实际检测端口是否 `LISTEN` |
| **操作日志** | 记录到 `/var/log/change_ssh_port.log` |

## 9. 防火墙与云安全组

### 9.1 本机防火墙

主脚本自动识别并处理：

- **ufw**：`ufw allow <端口>/tcp`
- **iptables**：追加 `ACCEPT` 规则（重启可能失效，建议持久化）
- **nftables**：仅提示，需手动确认规则（各发行版差异较大）

### 9.2 云安全组（必须手动）

阿里云 / 腾讯云 / AWS 等云服务器，需在控制台的**安全组**中放行新端口，否则本机监听正常也无法从外网连接。这一步脚本无法代劳。

## 10. 回滚手册

### 10.1 使用备份回滚

```bash
# 查看可用备份
ls -lt /etc/ssh/sshd_config_backups/

# 恢复最近一次
cp /etc/ssh/sshd_config_backups/sshd_config.<时间戳>.bak /etc/ssh/sshd_config
systemctl restart ssh
```

### 10.2 手动应急

若 SSH 完全连不上，可通过云控制台的 VNC / 救援模式登录后执行上述命令，或直接编辑 `/etc/ssh/sshd_config` 把 `Port` 改回原值。

### 10.3 查看日志

```bash
tail -n 50 /var/log/change_ssh_port.log
```

## 11. 常见问题 FAQ

**Q1：改完端口后连不上？**
先确认云安全组已放行新端口；再在服务器上 `ss -tlnp | grep sshd` 看实际监听端口。若旧端口还在（保留过渡），可先用旧端口登录排查。

**Q2：为什么还要保留旧端口？**
保留旧端口是为了在验证新端口期间保留一条退路，避免新端口配置有问题时被锁在门外。验证通过后运行收尾脚本关闭即可。

**Q3：脚本会改 `sshd_config.d/` 里的文件吗？**
只有在检测到其中存在 `Port` 指令、且你同意时才会注释掉（并备份）。否则不动。

**Q4：端口改成 80/443 会冲突吗？**
脚本会检测端口是否已被占用。若 80/443 已被 Web 服务占用会拒绝；若空闲则可用，但通常不建议与常见服务混用。

**Q5：支持 CentOS / Ubuntu 吗？**
支持。脚本基于 systemd 的 `ssh` 服务名，主流发行版通用；个别发行版服务名为 `sshd`，若重启失败可手动 `systemctl restart sshd`。

**Q6：能批量部署吗？**
可以，用非交互模式：
```bash
sudo bash change_ssh_port.sh -p 2222 -y --keep-old --firewall
```
配合 Ansible 等工具可批量执行。

> 通过管道执行时，参数需用 `bash -s --` 传入，否则会被 bash 自身消费。

### 14.2 本地执行与参数

```bash
sudo bash install.sh
sudo bash install.sh -d /usr/local/lib/ssh-port-tools -y --no-doc
```

| 参数 | 说明 |
| --- | --- |
| `-d, --dir DIR` | 安装目录，默认 `/opt/ssh-port-tools` |
| `-y, --yes` | 非交互，全部使用默认值 |
| `--menu` | 安装后直接打开交互面板 |
| `--run` | 安装后立即运行「更换端口」脚本 |
| `--no-alias` | 不注入 `sshh` 别名（只装命令，不动 shell 配置） |
| `--no-doc` | 不安装文档 |
| `--uninstall` | 卸载（删除目录、软链与别名块） |
| `-V, --version` | 显示版本 |
| `-h, --help` | 显示帮助 |

### 14.3 工作原理

- **自解压单文件**：内嵌 `base64(tar.gz)` 负载，运行时解压到临时目录；
- **完整性校验**：内置 sha256 清单逐个校验，失败即中止；
- **管道友好**：脚本从 stdin 读取自身负载后，交互提示自动改从 `/dev/tty` 读取，`curl | bash` 也能正常交互；
- **命令软链**：安装后创建 `ssh-port` / `ssh-port-menu` / `ssh-port-change` / `ssh-port-remove`；
- **别名注入**：向 `~/.bashrc`、`~/.zshrc` 写入带标记的 `alias sshh='ssh-port'`，幂等且可精确移除；不占用系统 `ssh` 命令；
- **sudo 正确落点**：用 `getent passwd "$SUDO_USER"` 反查真实 home，避免把别名写进 `/root` 而普通用户无效；
- **保持属主**：写入后把 rc 文件属主还原给原用户，避免 `sudo` 把 `.bashrc` 变成 root 所有；
- **可卸载**：`--uninstall` 清理目录、4 个软链与别名块。
- **仅限 Linux**：安装器检测到非 Linux 会直接拒绝运行（脚本依赖 `systemctl`、`/etc/ssh/sshd_config`）。

### 14.4 重新打包

脚本或文档更新后，重新生成 `install.sh`：

```bash
python build_install.py
```

> `install.template` 是模板源，`build_install.py` 负责打包并替换版本号、负载与校验清单。

### 14.5 安装后 `sshh` 不生效？

按顺序排查：

```bash
# 1. 确认别名已写入（sudo 安装时容易写错位置）
grep -A1 'ssh-port-tool' ~/.bashrc

# 2. 确认命令本身可用（不依赖别名）
ssh-port-menu --status

# 3. 让配置生效
source ~/.bashrc
```

若第 1 步没有输出，说明别名没写进你的 rc 文件：

- 用 `sudo` 安装时，安装器会通过 `SUDO_USER` 反查真实 home（v2.6 起）；
- 若你用的是 `su -` 切换 root，`SUDO_USER` 为空，此时可手动加一行：
  `echo "alias sshh='ssh-port'" >> ~/.bashrc`
- 或干脆不用别名：直接用 `ssh-port-menu`，行为完全一致。

### 14.6 安全建议

- 远程执行前建议先下载审阅：`curl -fsSL https://your.host/install.sh -o install.sh && less install.sh`
- 安装器需要 root；`--uninstall` 会 `rm -rf` 安装目录（已内置防 `/` 与空路径保护）。

## 15. 推送到 GitHub

### 15.1 前置准备

1. 安装 git：<https://git-scm.com/downloads>
2. 生成访问令牌（**不要用账号密码**）：
   - 打开 <https://github.com/settings/tokens/new>
   - Note 填 `ssh-port-tool`，Expiration 选 30/90 天
   - 勾选 **`repo`** 权限（私有仓库必需）
   - 生成后复制 `ghp_xxxxx`，**只显示一次**

> 本机实测 `github.com:22` 可能被网络阻断，因此推荐 **HTTPS** 方式（443 可用）。

### 15.2 一键推送（推荐）

```bash
bash push-to-github.sh
```

交互流程：

```
GitHub 用户名: yourname
仓库名（默认 debian-ssh-port-tool）: debian-ssh-port-tool
粘贴 Token（输入不回显）: ********
确认推送到 https://github.com/yourname/debian-ssh-port-tool ？(y/N) y
```

脚本会自动：校验 `.gitignore` → `git init`（如需）→ 配置提交身份 → `git add -A` → 提交 → 可选调用 API 建仓 → 添加 `origin` → 推送。

### 15.3 参数说明

| 参数 | 说明 |
| --- | --- |
| `-u, --user NAME` | GitHub 用户名 |
| `-r, --repo NAME` | 仓库名，默认 `debian-ssh-port-tool` |
| `--public` / `--private` | 仓库可见性，默认 **private** |
| `--https` / `--ssh` / `--local` | 推送方式，默认 HTTPS；`--local` 只本地提交不推送 |
| `-t, --token TOKEN` | 直接传 Token（不推荐，会留在 shell 历史） |
| `-y, --yes` | 跳过最终确认 |
| `-n, --dry-run` | 预演，只打印将执行的命令 |
| `-V` / `-h` | 版本 / 帮助 |

非交互（CI）用法：

```bash
GH_TOKEN=ghp_xxx bash push-to-github.sh -u yourname -r myrepo --public -y
```

### 15.4 Token 安全设计

| 环节 | 做法 |
| --- | --- |
| 输入 | `read -s` 静默读取，屏幕不回显 |
| 传输 | 通过**一次性** `credential.helper` 以环境变量传给 git，不出现在进程列表 |
| 存储 | 不写入 `.git/config`，不写入磁盘 |
| 建仓 API | Token 通过 `curl -K` 临时配置文件（600 权限）传入，用完即删 |

### 15.5 手动推送（等价命令）

```bash
git init -b main
git add -A
git commit -m "feat: Debian SSH 端口更换工具 v2.4"
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

推送时 git 会提示输入用户名和密码——**密码处粘贴 Token**。

### 15.6 常见问题

| 现象 | 原因 / 解决 |
| --- | --- |
| `Authentication failed` | Token 过期或未勾选 `repo`；重新生成 |
| `repository not found` | 仓库名大小写不符，或 Token 无权访问该账号 |
| `src refspec main does not match any` | 还没有任何提交，先 `git add -A && git commit` |
| `non-fast-forward` | 远程已有提交。脚本在**本地尚无提交时**会自动 fetch 并 `reset --soft` 对齐远程历史；若本地已有历史，需手动 `git pull --rebase --allow-unrelated-histories origin main` |
| `Failed to connect ... port 22` | SSH 22 被阻断，改用 `--https`，或配代理 |
| 网络超时 | `git config --global http.proxy http://127.0.0.1:7890` |

## 16. 交互面板与 sshh 命令

### 16.1 打开面板

安装器会在 `~/.bashrc`（及 `~/.zshrc`，若存在）写入：

```bash
# >>> ssh-port-tool >>>
# Debian SSH 端口管理工具：输入 sshh 打开交互面板
# 刻意不占用 ssh，避免与系统命令冲突；ssh 仍为原生客户端，行为不变
# 如需直接运行面板而不依赖别名：ssh-port
alias sshh='ssh-port'
# <<< ssh-port-tool <<<
```

之后新开终端（或 `source ~/.bashrc`），输入 `sshh` 即进入面板。

不想改 shell 配置时：

```bash
sudo bash install.sh --no-alias   # 安装时不注入别名
ssh-port-menu                     # 直接命令打开面板（任何时候都可用）
```

### 16.2 面板功能

| 选项 | 作用 | 说明 |
| --- | --- | --- |
| `1` | 查看 SSH 状态详情 | 配置文件、生效端口、监听明细、`Port` 指令、防火墙规则 |
| `2` | 更改 SSH 端口 | 调用 `change_ssh_port.sh`，含备份/校验/回滚全流程 |
| `3` | 移除旧端口 | 调用 `remove_old_ssh_port.sh`，禁止移除最后一个端口 |
| `4` | 备份与回滚 | 列出 `/etc/ssh/sshd_config_backups/`，选编号回滚并重启 |
| `5` | 防火墙规则 | 展示 `ufw`/`nftables`/`iptables` 现状，可按当前端口补放行 |
| `6` | 重启 SSH 服务 | 重启后逐个验证端口是否 `LISTEN` |
| `7` | 查看操作日志 | `tail` 最近 30 行 `/var/log/change_ssh_port.log` |
| `8` | 卸载本工具 | 清理别名块、软链、安装目录 |
| `0` | 退出 | — |

非 root 运行时，需要写操作会自动通过 `sudo` 提权（会提示输入密码）。

### 16.3 `sshh` 与 `ssh` 的关系（重要）

| 你输入 | 实际执行 |
| --- | --- |
| `sshh` | 打开管理面板 |
| `sshh user@host` | 转发到原生 SSH 客户端，参数原样透传 |
| `ssh user@host` | 原生 SSH 客户端，**与本工具无关** |
| `ssh -p 2222 user@host` | 同上 |
| `ssh -V` | 同上，显示原生客户端版本 |
| `ssh-port` / `ssh-port-menu` | 不依赖别名，直接开面板 |

**为什么用 `sshh` 而不是 `ssh`？**

v2.5 曾经用 `alias ssh='ssh-port'` 接管 `ssh`，但这样会和系统命令冲突：
脚本里写 `ssh host`、编辑器插件调用 `ssh`、`rsync -e ssh` 等场景都会受影响，
排查起来很费劲。

v2.6 起改为 `sshh`，彻底规避冲突：

1. 原生 `/usr/bin/ssh` **原封不动**，任何场景下的 `ssh` 行为都不变；
2. 只新增 `/usr/local/bin/ssh-port` 等命令；
3. 用 `alias sshh='ssh-port'` 提供面板入口；
4. 想用面板又不想依赖别名：`ssh-port` 或 `ssh-port-menu`。

> 从 v2.5 升级：安装器会按标记自动替换旧配置块，旧 `alias ssh` 会被移除。
> 当前已打开的终端里可能仍有残留，执行 `unalias ssh` 即可清除。

### 16.4 非交互用法

面板脚本支持只输出状态，便于接入监控或巡检脚本：

```bash
ssh-port-menu --status
```

输出示例：

```text

生效端口  : 22 2222
监听状态  : 22(监听) 2222(监听)
服务状态  : active running
防火墙    : ufw active
配置校验  : 通过
最近备份  : sshd_config.20261102-201500.bak
安装目录  : /opt/ssh-port-tools
脚本版本  : v2.8
```

### 16.5 卸载

三种方式等价：

```bash
# 1. 面板里选 8
sshh

# 2. 命令行（安装目录里不含 install.sh，需重新下载）
curl -fsSL "https://cdn.jsdelivr.net/gh/Swordee/NEW1@v2.8/Debian%20SSH/install.sh" | sudo bash -s -- --uninstall

# 3. 手动清理
rm -f /usr/local/bin/ssh-port /usr/local/bin/ssh-port-menu \
      /usr/local/bin/ssh-port-change /usr/local/bin/ssh-port-remove
rm -rf /opt/ssh-port-tools
# 再从 ~/.bashrc / ~/.zshrc 删除 "# >>> ssh-port-tool >>>" 到 "# <<< ssh-port-tool <<<" 之间的内容
```

> 卸载会清理：安装目录、4 个软链（`ssh-port` / `ssh-port-menu` / `ssh-port-change` / `ssh-port-remove`）、
> 以及 `~/.bashrc`、`~/.zshrc` 里的别名块。
> **不会**动 `sshd_config`、备份目录和你的其他 shell 配置。
